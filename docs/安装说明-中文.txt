【四】游戏内怎么用 / 应该看到什么
· 正常玩法完全不变：按住到满蓄（约 2.5 秒）松手 = 正常满蓄弹；点射、短蓄力照旧。
· "定时炸弹"玩法：按住不放 → 约 2.6 秒进入过充 → 过充后继续按住到满 7 秒（合计约 9.6 秒）
  → 武器在手中过充爆炸（游戏本体的 PLAS-45 过充爆炸），此时不发射弹体。
· 在过充期间（约 2.6~9.6 秒之间）松手 = 正常满蓄射击，计时作废；再按住重新计时。
· 两个注意点：
  - 引信只在"按住过充"时走：不按的时候不倒数、带在身上不会自己炸（自动引信+提示音那种完整
    玩法只有 Runtime 版能做）。
  - 独立版没有提示音（纯改数据做不了声音）；逐秒升调提示音是 Runtime 版的特性。

【七】Durable Damage Delete 0.1.3 —— 崩溃冲突结论（第三方模组，不能改它，只能隔离）
· 它依赖谁：它的 hd2runtime.json 要求模块 mods/skyeshade/hd2runtime（≥0.28.1）。
  - 没装 HD2Runtime 时：Bingus 日志报 module 'mods/skyeshade/hd2runtime' not found，
    它自己加载失败（游戏不崩，但它完全无效）。
  - 装上 HD2Runtime 0.40.0 后：它走 0.40.0 的"旧版兼容通道"。HD2Runtime.log 第 154 行原文：
    "legacy SDK 0.28.1 operation from mods/aldarrin/durable_damage_delete: PLAS-45 Epoch
     damage.primary.durable_damage needs allow_unverified_effect=true since SDK 0.30.0 and is
     applied without it, as SDK 0.28.1 allowed. ..."
    → 即：它未经新 SDK 的安全验证门，直接对纪元数据写入（runtime 作者明确警告的点）。
· 崩溃时间线（读日志）：
  - 20:36:09 会话：全部模组加载成功（其中包含 Durable 与 HD2Runtime，HD2Runtime.log 最后一条
    写于 20:36:18）→ 约 10 余秒后崩溃：exception 0xC0000005 at helldivers2.exe+0x66D1FF，
    转储 helldivers2.exe.27936.dmp（20:36:26）。
  - 如实补充：在你加入 Durable 之前（20:16–20:34 期间）也已有至少 7 个崩溃转储（两套崩溃签名
    交替出现）。所以准确说法是：崩溃与「HD2Runtime 0.40.0 + BSL v19」这套组合强相关；
    Durable 是唯一"强制拉上 HD2Runtime"的模组 —— 想开 Durable 就等于把游戏带回这套会崩的组合。
· 处理（我们不动它的文件）：
  1) Echelon 里保持「Durable Damage Delete 0.1.3」= 禁用 + 未部署；
  2) 「HD2Runtime 0.40.0」也保持禁用（它就是崩溃组合的另一半）；
  3) 想恢复用它只有两条路（都需要作者动手，你不能改、我也不改）：
     作者用 SDK ≥0.30 重新导出；或给该操作加 allow_unverified_effect=true。
· 给作者的反馈模板（英文，直接复制给他）：
  "Hi! Your mod seems to be exported with HD2Runtime SDK 0.28.1. On HD2Runtime 0.40.0 it is

   needs allow_unverified_effect=true since SDK 0.30.0 and is applied without it, as SDK 0.28.1

   project to SDK 0.30.0+ and re-export (or add allow_unverified_effect=true) and test against
   the current game build? Thanks a lot!"

【十一】BSL 兼容性：v2.3 修掉的 bug（重要）
· 问题（v2.0–v2.2）：加载时用 rawset(_G,'update', 自己的钩子) 顶掉了原来的每帧钩子，而代码里
  用来记原始钩子的 original_update 从来没有被赋值 → 等于"把别人的钩子拔掉"。后果：本模组一加载，
  所有先于它加载的 BSL 模组（含 BSL 框架自带的那一批）每帧逻辑全部停摆。
  · 你机器上的证据：21:36 那次启动（未加载本模组）VehicleCooldown 每 60 秒一条心跳
    （uptime=37/97/157/217s）；21:41 那次启动（加载了本模组）整个 3 分 37 秒只有开局两行、
    之后没有任何心跳。
· 修复（v2.3）：装钩子之前先 rawget(_G,'update') 记住上一个，每帧调用它；没有上一个才自己装。
  日志里会写 "Update hook: chained."（没有旧钩子时是 installed）。
· 离线验证（不启动游戏、不附加进程）见 兼容性验证-与BSL同装\（脚本 + results.txt）：
  ① 用 BSL 本体自己的发现规则（从你机器已安装的 BSL v19 补丁里抽出）命中本模组补丁；
  ② 85 个已部署补丁全量扫描：mods/hexua/epoch_timebomb_standalone 资源名唯一，不撞别人；
  ③ 沙盒（游戏自带 lua51.dll + 与 BSL 同接口的 loader 桩）3 场景全过：loader 在场正常写入、
     loader 在场冲突拒写、loader 不在场回退；且 loader 的 update 链仍被调用（帧计数 8 > 0）；
  ④ 你机器真实会话：BSL 日志 43 loaded / 0 failed，其中 mods/hexua/epoch_timebomb_standalone: loaded。
· 一句话：v2.0–v2.2 确实会"挤掉"别的 BSL 模组的每帧逻辑；v2.3 已经不会了，可以放心发布。
